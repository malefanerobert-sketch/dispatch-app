🔴 Master Agent Switch

The kill-switch for the entire Agent. When OFF, the Railway worker skips every discovery and apply run for every user — no tokens spent, no jobs applied. Individual account pause/reactivate still works; this is the fleet-wide override on top of that. Default: OFF. Turn ON only when you're ready to serve real users.

⚫ OFF — agent is standing down
No worker activity, no API tokens spent.

⏰ Agent Time Window

When the Agent runs. The worker only performs discovery inside this window — outside it, the run exits immediately and no tokens are spent. Set start and end hour (0–23) and the timezone they're expressed in. Master switch still applies on top of this: if it's OFF, nothing runs regardless of the window.

➕ Add New Job Source

Add a new job source that every user can enable in their settings. All sources are automatically country-filtered to South Africa and become available to all existing accounts on save.

Shared AI key

One DigitalHouse-owned key powers the Agent for every JobAgent user — match scoring, CV/cover letter/motivational letter drafting, reading a user's Watched pages, and applying on their behalf. Users never see or manage this (they only ever see the word "Agent" in the app); the cost is recovered through their subscription, not billed to their own accounts.

This is used for match scoring and for reading a user's Watched pages to find job postings — the default here is Claude Sonnet 5 for Anthropic / GPT-4o-mini for OpenAI. Paste any valid model string from your provider to override the default. Anthropic retires older model snapshots periodically — if scoring or page-reading silently stops working, check whether the model string here is still current.

This key is stored in dispatch_settings and read directly by the Railway worker (discoverWatched.js/apply.js) on every run — no further backend change is needed when you update it here.

Agent instructions

Free-text guidance prepended to the prompt the Agent uses when it reads a user's Watched pages to work out which links are real job postings. Use this to steer judgement calls — e.g. what to treat as a "job posting" vs. navigation, how to handle listings with no clear title, or any site-specific quirks you've noticed.
